## Overview

Understanding an unfamiliar codebase is slow. **Git Repo Analyzer** shortens that process: give it a GitHub repository URL, and it clones the repo, splits the code into chunks, converts them into vector embeddings, and stores them in a vector database. You can then ask natural-language questions such as:

- *"What does this project do?"*
- *"Where is authentication handled?"*
- *"Explain how the main pipeline works."*

Answers are generated by a Large Language Model (LLM) grounded in the code that was actually retrieved from the repository, which keeps responses relevant and reduces hallucination.

## Features

- **Load any public GitHub repository** by URL
- **Semantic code search** powered by vector embeddings
- **Context-aware answers** generated by an LLM using retrieved code
- **Web interface** for asking questions interactively
- **Modular architecture** with separate components for loading, embedding, storage, retrieval, and generation
- **Centralized logging and custom exception handling** for easier debugging

## How It Works

```
 GitHub URL
     │
     ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────────┐
│  Clone Repo  │ -> │ Chunk Files  │ -> │ Create Embeddings│
└──────────────┘    └──────────────┘    └────────┬─────────┘
                                                 │
                                                 ▼
                                        ┌──────────────────┐
                                        │   Vector Store   │
                                        └────────┬─────────┘
                                                 │
 User Question ──────────────────────────────────┤
                                                 ▼
                                        ┌──────────────────┐
                                        │    Retriever     │
                                        │ (top-k relevant  │
                                        │      chunks)     │
                                        └────────┬─────────┘
                                                 │
                                                 ▼
                                        ┌──────────────────┐
                                        │       LLM        │
                                        └────────┬─────────┘
                                                 │
                                                 ▼
                                        Grounded Answer
```

1. **Load**: the repository is cloned locally and its files are read.
2. **Embed**: file contents are split into chunks and converted to embeddings.
3. **Store**: embeddings are saved in a vector store for fast similarity search.
4. **Retrieve**: for each question, the most relevant chunks are fetched.
5. **Generate**: the LLM answers using the retrieved chunks as context.

## Getting Started

### Prerequisites

- Python 3.10 or higher
- [Git](https://git-scm.com/) installed and available on your `PATH`
- An API key for your chosen LLM provider (see [Configuration](#configuration))

### Installation

1. **Clone the repository**

   ```bash
   git clone https://github.com/charan-d11/Git_Repo_Analyzer.git
   cd Git_Repo_Analyzer
   ```

2. **Create and activate a virtual environment**

   ```bash
   # Windows
   python -m venv venv
   venv\Scripts\activate

   # macOS / Linux
   python3 -m venv venv
   source venv/bin/activate
   ```

3. **Install dependencies**

   ```bash
   pip install -r req.txt
   ```

   Optionally, install the project in editable mode:

   ```bash
   pip install -e .
   ```

## Configuration

Create a `.env` file in the project root and add your credentials:

```env
# Replace with the key for the LLM provider you use
API_KEY=your_api_key_here
```

Other settings (model names, chunk size, number of retrieved results, etc.) can be adjusted in `app/config/config.py`.

> **Note:** Never commit your `.env` file. It is already excluded if listed in `.gitignore`.

## Usage

1. **Start the application**

   ```bash
   python app/app.py
   ```

2. **Open your browser** at the address shown in the terminal (typically `http://127.0.0.1:5000`).

3. **Enter a GitHub repository URL** and wait for it to be indexed.

4. **Ask questions** about the codebase in the chat box.

Cloned repositories are stored under `data/repos/`, which is git-ignored.
